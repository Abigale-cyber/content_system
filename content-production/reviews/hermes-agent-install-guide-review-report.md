# 《养虾转养马第一步：把 Hermes Agent 装起来》对抗式内容审稿

## 裁定

**结论：需修改。**

这版已经比普通安装教程好很多，标题和“养虾/养马”的梗有记忆点，也能把安装步骤讲清楚。但问题是：正文后半段仍然偏“说明书集合”，公众号阅读的情绪线不够强，读者容易在中段进入“我知道了，先收藏吧”的状态，然后离开。

## 笔杆子审

1. **开头有梗，但钩子还不够狠。** 现在的开头是在解释文章不讲什么、只讲什么，逻辑清楚，但冲突感不够。公众号读者更容易被“你其实还没入门，只是在云养马”这类判断拉住。
2. **结构太顺，缺少节奏变化。** 安装、配置、启动、体检、命令、常见坑，都是正确内容，但排布像教程目录。需要把“为什么先 CLI”“为什么不要先接微信”“为什么能聊天不等于跑通”变成文章主线，而不只是操作提醒。
3. **重复信息偏多。** `hermes model`、`hermes doctor`、WSL2、先 CLI 再 Gateway 被多次重复，读者会感觉信息密度下降。
4. **案例感不足。** 文中有判断，但缺少更像真人的踩坑场景，比如“装完能聊天就以为成功，结果文件读不了”“第一天就接微信，最后分不清是模型、工具还是 Gateway 坏了”。
5. **结尾有观点，但还可以更公众号。** “谁先让 Agent 开始干活”是好句子，但前面铺垫如果更有冲突，结尾会更有力。

## 参谋审

目标读者不是工程师，而是想从 OpenClaw/Hermes 这类 Agent 工具里获得生产力的人。对他们来说，最重要的不是完整命令百科，而是：

- 我现在该不该装？
- 先做哪一步？
- 哪些东西第一天不用碰？
- 怎么判断自己真的跑通了？
- 出错时先查哪里？

因此修改方向不是增加更多技术细节，而是把文章改成“新手第一天跑通路线图”：少一点百科，多一点判断；少一点命令堆叠，多一点避坑逻辑。

**综合分：7.0 / 10，需修改。**

## 修改策略

1. 保留原标题，不更换已定标题。
2. 开头改成“别再云养马”的强判断，快速制造读者代入。
3. 把全文主线改成：**第一天不要追求全能，只跑通最小闭环。**
4. 保留必要命令，但减少重复解释。
5. 强化小白视角：每一步说明“这一步是在验证什么”。
6. 结尾改成行动号召：今天只做一件事，把 Hermes 牵进门。
