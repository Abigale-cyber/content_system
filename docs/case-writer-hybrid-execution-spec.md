# `case-writer-hybrid` 执行说明

## 1. 这个 Skill 做什么

把一个观点型输入，扩展成一篇有案例支撑、有结构推进的公众号长文。

它不是简单续写，而是负责：

1. 识别核心观点
2. 拆出 3 条可展开的论证路径
3. 为每条路径补案例或证据线索
4. 收敛成一份 Markdown 主稿

## 2. 输入

推荐输入文件：

- `docs/stage1-sample-brief-ai-content-system.md`
- 或按 `docs/stage1-brief-template.md` 自行填写的一份 brief

输入最少应包含：

- `topic`
- `target_reader`
- `publish_goal`
- 核心观点
- 至少 3 条论证方向

## 3. 输出

主输出：

- `content-production/drafts/{slug}-article.md`

可选补充输出：

- 三路径草稿对比
- 评分记录
- 案例候选列表

> 当前阶段允许只保留最终主稿，不强制保留全部中间竞写结果。

## 4. 标准输出结构

建议主稿结构如下：

1. 标题
2. 导语
3. 问题提出
4. 核心观点展开
5. 2 到 3 个案例或论据
6. 结论与行动建议

## 5. 执行步骤

1. 读取 brief，提炼一句话核心判断。
2. 生成 3 条不同论证路径，例如：
   - 路径 A：问题拆解型
   - 路径 B：案例驱动型
   - 路径 C：方法论总结型
3. 为每条路径补充案例或论据。
4. 评估哪条路径最适合目标读者与发布目标。
5. 基于最优路径输出 Markdown 主稿。

## 6. 质量标准

- 文章不能只有观点，必须有论证推进
- 文章不能只有案例堆砌，必须回到核心判断
- 语言要适合公众号，不写成论文或报告
- 不直接产出 HTML

## 7. 建议提示方式

如果是手动调用，可直接使用下面的任务说明：

```md
请你扮演 `case-writer-hybrid`。

任务：
把这份观点 brief 扩写为一篇公众号长文。

要求：
1. 先识别核心观点
2. 给出 3 条不同论证路径
3. 为每条路径补充案例或论据
4. 选择最优路径，输出一篇完整 Markdown 主稿
5. 文章适合公众号阅读，不输出 HTML
6. 优先保证结构完整、观点鲜明、案例能支撑论点
```

## 8. 本阶段最重要的约束

- 输出必须是 `drafts/*-article.md`
- 不跳到配图或排版步骤
- 如果案例不够，宁可先写明“案例线索待补”，也不要编造事实
