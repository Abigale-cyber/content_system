# Content System 日常使用说明

> 这份文档不是命令手册。你不需要记命令，也不需要知道底层怎么调用 skill。
>
> 你只需要告诉我你想做什么，我会判断该启用哪个 skill、按什么顺序跑、什么时候该停下来让你确认。

如果你想看底层运行命令、输入输出路径和 workflow 名称，再去看：

- [runtime-usage.md](./runtime-usage.md)

## 最新新增 Skill

这一轮重点补进来的 skill 是：

- `topic-radar`：先拆选题，不要上来就写
- `adversarial-content-review`：主稿写完先独立审稿，再决定能不能继续包装
- `script-writer-short`：主稿稳定后再复用成短视频口播稿

## 最重要的一句话

你日常只需要这样说：

```text
用这个素材跑完整链路
```

或者：

```text
先帮我拆一下这个选题
```

我会根据素材状态，决定是先找选题、先查资料、先整理 brief，还是直接写稿。

## 正确的内容生产顺序

完整内容生产不是“先写再查”，而是：

```text
先找热点 / 找素材
-> 拆选题角度
-> 查资料 / 深研 / 看竞品
-> 整理 brief
-> 写主稿
-> 审稿
-> 必要时去 AI 味
-> 配图
-> 排版
-> 预览发布
```

如果你已经有明确题目和素材，可以跳过前几步，直接从 brief 或写稿开始。

## 最常用的几句话

### 1. 从热点到公众号

你说：

```text
用这个热点跑完整公众号链路
```

我会按这个顺序处理：

```text
拆选题角度
-> 必要时深研
-> 整理 brief
-> 写主稿
-> 审稿
-> 审稿通过后配图
-> 排版
```

如果审稿不过，我会停下来告诉你问题，不会继续配图和排版。

### 2. 先只拆选题

你说：

```text
先帮我拆一下这个选题
```

我会输出：

- 哪几个角度能写
- 哪个角度最值得写
- 目标读者是谁
- 素材够不够
- 还缺什么资料

### 3. 先做深研

你说：

```text
围绕这个题做一下深研
```

我会先查资料和来源，再把结论整理给你。

适合用在：

- 事实不确定
- 涉及新趋势
- 需要数据或案例
- 你怕文章写空

### 4. 直接写公众号

你说：

```text
用这个 brief 出主稿
```

或者：

```text
用这个素材写一篇公众号
```

我会先判断素材够不够。如果不够，我会先建议补 brief 或做深研；如果够，就进入写稿。

### 5. 审稿

你说：

```text
审一下这篇，看看能不能发
```

我会从三种视角审：

- 笔杆子：结构、论点、证据
- 参谋：读者是否看得懂、有没有共鸣
- 裁判：给出分数和结论

结论会是：

- `通过`
- `需修改`
- `需重写`

### 6. 转短视频

你说：

```text
把这篇改成 90 秒口播稿
```

我会输出：

- Hook
- Introduction
- Body
- Summary
- 拍摄提示

## 各 Skill 用人话解释

### `topic-radar`

帮你判断一个热点怎么写。

你可以说：

```text
这个热点能怎么写？
```

它适合在最前面用。

### `topic-research`

帮你查资料、补来源、补事实。

你可以说：

```text
围绕这个题做一下深研
```

它应该在正式写稿前用。

### `content-brief-builder`

把零散想法整理成正式写作 brief。

你可以说：

```text
把这个题整理成 brief
```

它是写稿前的地基。

### `case-writer-hybrid`

根据 brief 写公众号主稿。

你可以说：

```text
用这个 brief 出主稿
```

它会自动做结构、论证、故事共鸣、模板味和基础去 AI 味检查。

### `adversarial-content-review`

独立审稿，判断能不能继续发布。

你可以说：

```text
审一下这篇，看看能不能发
```

审稿不过时，应该先改稿，不要继续排版。

### `humanizer-zh`

单独去 AI 味。

你可以说：

```text
把这篇去一下 AI 味
```

它适合在你觉得文章“像机器写的”时使用。

### `script-writer-short`

把文章改成短视频口播稿。

你可以说：

```text
把这篇改成 90 秒口播稿
```

它适合在主稿稳定之后使用。

### `generate-image`

生成文章配图。

你可以说：

```text
给这篇生成配图
```

### `wechat-formatter`

把 Markdown 排成公众号 HTML。

你可以说：

```text
把这篇排版成公众号 HTML
```

### `wechat-studio`

人工预览和包装工作台。

你可以说：

```text
打开工作台看一下排版和配图
```

它不是必须步骤，但适合发布前人工检查。

### `wechat-collect`

从公众号链接采集文章，并转成可写 brief。

你可以说：

```text
采集这篇公众号，转成 brief
```

### `wechat-report`

找多篇公众号竞品做对比。

你可以说：

```text
围绕这个主题找几篇公众号做对比
```

### `news-collect`

扫资讯，找热点。

你可以说：

```text
帮我扫一下最近有什么值得写
```

### `feishu-user-auth` / `feishu-bitable-sync`

飞书相关能力，不属于日常写稿主链路。

你可以说：

```text
把这个报告同步到飞书多维表
```

我会判断是否需要先做授权。

## 什么时候该停下来

下面几种情况，不应该继续往后跑：

1. 选题角度不清楚  
   先做 `topic-radar`。

2. 事实和资料不够  
   先做 `topic-research` 或 `wechat-report`。

3. 没有正式 brief  
   先做 `content-brief-builder`。

4. 审稿结论是 `需修改` 或 `需重写`  
   先改稿，不要继续配图和排版。

5. 只是想测选题，不要直接跑完整公众号链路  
   先说“先帮我拆一下这个选题”。

## 真实测试时你怎么开始

你只需要准备一份素材，然后对我说：

```text
用这个素材跑完整链路
```

素材可以很简单：

```text
这是我想写的热点：
……

我想写给：
……

我手上有这些素材：
……
```

如果素材不够，我会先告诉你缺什么；如果素材够，我会继续往下跑。

## 你不需要做什么

你不需要：

- 记住命令
- 判断该用哪个 skill
- 手动拼接文件路径
- 自己决定 workflow
- 自己判断什么时候该停

这些由我来处理。

你只需要说清楚目标和素材。
